# 패유기 개선 사항 리스트

남은 개선 과제만 정리. 완료되어 제외된 항목은 git 히스토리 참조. 원본 규칙·연출의 근거는 `../sq/RULES.md`, `../sq/FX.md`.

## 1. CPU AI·캐릭터 성격 — 원본 정합
원본의 캐릭터 성격은 스킬 판단 표로만 표현되고, 버림·리치·론 판단은 캐릭터와 무관하다(`RULES.md` 5·6·7절).
- CPU 스킬 판단을 원본 표로 교체: 캐릭터별 조건·확률(6.4), MP 하한과 소모가 다른 스킬(린샹 B, 페톰 A), 리치 중 사용 불가·라운드당 한 번 제한(6.2), 교환 스킬의 칸 선택 규칙(6.5). 지금의 `aiScore`+문턱값 구조를 대체한다.
- 버림패 `aiProfile` 축 처리 결정: 무작위 손패 측정에서 선택을 바꾸는 경우가 드물고 대부분 근소차 타이브레이크(`tests/perf/AIPROFILE.md`). 원본은 전 캐릭터 동일·결정적(동률만 무작위).
- `luck`(CPU 드로우 편향) 존폐 결정: 원본에 해당 코드가 없다(7.4). 지금은 캐릭터 승률을 맞추는 손잡이로 쓰고 있다.
- CPU 펑: 원본 CPU는 펑을 하지 않는다(3.5). 원본대로 끌지, 캐릭터성으로 남길지 결정.
- CPU 리치 확률: 원본은 스테이지에 비례(`(스테이지×200+1)/1000`), 웹은 실력 값 기반.

## 2. 전투 연출 — 잔여
선언·나가리·흔들림·결과 창·라운드 페이드는 원본 타임라인으로 교체됨(`STRUCTURE.md` "전투 연출").
- 효과음: 원본은 론·쯔모 SFX 7 + 승리 징글(BGM 8/9), 나가리 착지 SFX 9, 피해 SFX 13. 웹은 `gong`, 공격자별 `slash`/`impact` 랜덤.
- 스킬 연출, 마유 난입, 패 이동, 손패 공개, HP 막대 감소 속도: 원본이 스크립트가 아니라 EXE 네이티브로 그려 타임라인을 못 뽑았다(`FX.md` 4.8). 맞추려면 해당 네이티브부터 역분석.

## 3. 모바일
- 간헐적으로 페이지가 아래로 밀려 툴바·게임 화면 윗부분이 브라우저 주소창 밑으로 들어간다(아이폰 크롬에서 확인). `body`의 `min-height: 100vh`와 게임패드 하단 여백, 전체 화면 대체 모드의 `100vh`가 후보.

## 4. 별도 튜토리얼 추가 검토
- **목표:** 규칙(패·역·스킬·조작)을 가르치는 별도 튜토리얼 도입 여부 검토.
- **참고:** 도입 시 진입점(타이틀 메뉴?)·범위(인터랙티브 vs 정적 안내) 결정 필요. 우선 "검토" 단계.

## 5. 코드 구조 리팩토링 — 잔여
구조/제약은 STRUCTURE.md 참조. 완료분은 git 히스토리.
- `battleEngine.js`의 `updateBattleMusic`/`showPopup`/`setExpression`을 이벤트 발행으로 — 발화 타이밍이 한 프레임 밀릴 수 있어 순수 이동이 아님. 착수 시 사운드 스파이(`getSfxIds`)로 발화 순서를 전후 비교할 것.
- `checkActionButton`/`checkExchangeButton`의 rect를 온디맨드 계산으로 바꿔 그리기 의존을 끊을지 검토. 바꾸면 `mouse.spec.ts`의 "그리기 전 false" 단언 갱신.
- ESM 전환은 테스트 하네스 재작성을 동반하므로 보류.

## 6. 테스트 안전망 — 잔여
- EndingScene/CreditsScene/EncounterScene 확인키는 실제 키 입력 테스트 없음(씬을 `update()` 직접 호출로만 구동).
- 연출 타임라인 재생(조각 위치·대기·건너뛰기)을 직접 단언하는 테스트 없음. 전투 테스트가 스폰과 `isBlocking` 게이팅을 간접적으로 지날 뿐.
- 전체 스위트 간헐 실패의 기전 미확정(`retries: 1`로 실용 대응). 조사한다면 30분 타임박스.

## 7. 온라인 대전 준비 — 잔여
- P1 자리에 `AIController`를 끼워 대칭 모드·자동 테스트의 P1 AI(`autoPlay.js`, `tryP1AiPon`, `updateLogic`의 `symmetric` 분기, `HumanController` 안의 `symmetric` 분기)를 컨트롤러 교체로 바꾼다. `_ai_fingerprint` 베이스라인이 걸려 있으므로 측정값을 전후 비교한다.
- 온라인 4단계: 릴레이 서버(Cloudflare Worker + Durable Object, WebSocket 전송 구현, `transport.js`와 같은 인터페이스). 지금 로비의 방 코드·초대 링크 UI는 `BroadcastChannel`(같은 브라우저)에서만 통한다. 끊김은 매치 무효로만 처리하므로 재접속은 그 뒤.
- 퀵 매치: 릴레이가 대기 중인 상대를 자동으로 붙여 준다. 코드·초대와 병행하고 `vs.html` 로비에 버튼으로 더한다. 릴레이 뒤에야 가능.
