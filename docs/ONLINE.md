# 온라인 대전 설계

두 사람이 각자의 브라우저에서 1:1로 붙는 모드. 코드 구조의 전제는 `STRUCTURE.md`, 규칙은 `../sq/RULES.md`.

## 1. 방식

양쪽 클라이언트가 각자 `BattleEngine`을 그대로 돌리고, 서로 **행동(의도)만** 주고받는다. 틱 단위 락스텝은 쓰지 않는다.

- 엔진의 논리 진행은 행동 순서로만 결정된다. 틱은 연출 대기와 생각 시간에만 쓰이므로, 리치 대답·결과 창의 확인키 넘김은 각자 알아서 하고 상대 행동은 로컬 엔진이 받을 수 있는 상태가 될 때까지 큐에 둔다.
- 각 클라이언트에서 `engine.p1` = 나, `engine.cpu` = 상대. 렌더러·씬·테스트가 두 필드를 읽는 곳은 그대로 둔다.
- 숨은 정보는 지키지 않는다. 양쪽이 전체 상태를 가지므로 개발자 도구로 상대 패를 볼 수 있다. 서버 권위 방식(서버가 덱을 쥐고 각자 패만 보냄)은 엔진을 서버에서도 돌려야 해서 범위에서 뺀다.
- 두 화면은 같아야 한다. 판·연출·배경이 양쪽에서 동일하도록 전투 안의 무작위는 전부 공유 시드 난수에서 나온다(3절). 예외는 상대 캐릭터만 하는 대사(버림 대사, 펑 대답)로, 각자 자기 상대의 말풍선만 본다. 난수 소비는 양쪽이 같게 하고 보여 주기만 가른다(사용자 결정).

## 2. 자리 대칭화

구현됨(`STRUCTURE.md` "자리와 컨트롤러"). 엔진은 자리 무관 적용 함수(`drawFor`·`discardFor`·`declarePon`·`declareRiichi`·`declareTsumo`·`declareRon`·`confirmTileExchange`·`activateLastChance`)만 가지고, 자리마다 컨트롤러(`logic/seatControllers.js`의 `HumanController`·`AIController`)가 결정을 내려 그 함수를 부른다.

- 컨트롤러가 답하는 지점: 뽑기 창(펑·그냥 뽑기), 차례(리치·쯔모·비기·버림), 내 론에 대한 반격 비기(초발도·론 교환) 응답, 라운드 시작 패 교환, 나가리의 라스트 찬스, 룰렛 자동 정지 여부. 론은 리치 중 화료패가 나오면 규칙상 자동이라 결정이 아니고, 양쪽 엔진이 스스로 건다. 따라서 4절의 `ron` 메시지는 필요 없다.
- AI 컨트롤러는 옛 코드를 그대로 옮겨 동기로 답하고, 생각 시간은 `update` 훅이 `engine.timer`로 잰다.
- 네트워크 컨트롤러(`net/netController.js`)는 모든 통지에서 결정하지 않고 답을 받을 `resolve`만 보관하며, 메시지가 오면 같은 적용 함수를 부른다. 상대 자리는 `STATE_CPU_TURN` 안의 `cpuPhase`(`draw` → `turn`)로 어느 메시지를 기다리는지 안다. 엔진은 상태와 무관하게 매 틱 컨트롤러의 `poll`을 불러 큐를 비울 기회를 준다.
- 순서 의존 로직은 자리 번호(호스트 0, 게스트 1, `engine.localSeat`) 기준이다: 배패·라운드 시작 셋업은 자리 1부터, 선공 `firstSeat`, 라스트 찬스는 자리 0부터. 각 클라이언트에서 `engine.p1`은 여전히 자기이고 `whoAt(seat)`이 자리와 `P1`/`CPU`를 잇는다.
- 승리 때 도라 폭진은 `onDoraBomb` 통지로 묻고 답을 `doraBomb` 메시지로 보낸다. 상대 론 교환 뒤 어느 패를 다시 버릴지는 자기 차례의 `discard`로 온다. 룰렛 자동 정지 위치는 `rouletteStopAt` 통지이고 네트워크 컨트롤러는 `lastChanceStop` 메시지가 올 때까지 멈추지 않는다.

## 3. 무작위

전투 중 `Math.random`을 쓰지 않고 `engine.rng`(시드 난수)만 쓴다. 호스트가 매치 시작 때 시드를 보낸다. 용도별 스트림으로 나눠, 한 용도의 소비 순서가 어긋나도 다른 용도가 흔들리지 않게 한다.

- `deck`: 셔플, 도라·우라도라, 선공, `luck` 드로우 편향. 뽑기는 양쪽에서 같은 논리 순서로 일어난다.
- `fx`: 전투 배경, 대사 발동 확률과 대사 선택, 도라 룰렛 회전 수. 대사는 버림·펑·비기·승패 같은 논리 이벤트에서만 발동하므로 양쪽 소비 순서가 같아야 한다. 그래서 `fx` 소비는 자리에 무관하게 한다: 어느 자리가 버리든 대사 확률을 굴리고 대사까지 고르되, 말풍선은 그 자리가 상대일 때만 띄운다(펑 대답도 같은 규칙). 상태 해시에 `fx` 소비 횟수를 넣어 어긋남을 잡는다.
- `ai`: AI 판단 전부(비기 사용·반응, 론 교환에서 되가져올 패, 라운드 시작 교환, 라스트 찬스 자동 정지 위치, 버림·리치·펑 확률). 사람·원격 상대는 쓰지 않으므로 온라인에서는 동기화 대상이 아니다. 시드만으로 오프라인 경기를 재현하려고 같은 체계에 둔다.

구현은 `STRUCTURE.md` "난수". 시드는 `BattleEngine.init`의 `data.seed`(32비트)로 받아 `engine.seed`에 남는다. 행동은 `engine.actionLog`에 `{ round, who, type, ...payload }`로 쌓인다(버린 패는 `{ type, color }`).

메시지는 의도만 싣고 결과를 싣지 않는다. 사람이 키로 멈추는 라스트 찬스 룰렛만 정지 위치가 의도다.

온라인에서 끄는 것: easy 드로우 어시스트. 두는 것: `luck`(캐릭터 특성), 비기.

시드와 행동 로그를 저장하면 그대로 리플레이가 된다. 1차 범위에는 넣지 않는다.

초상화 눈 깜빡임은 프레임 기반 애니메이션이라 시드를 줘도 주사율에 따라 어긋난다. 판에 영향이 없으므로 로컬 그대로 둔다.

## 4. 메시지

행동한 쪽이 보내고, 자리 기준(보낸 사람 자리)이다.

| 메시지 | 내용 |
|---|---|
| `hello` | 접속 인사. 호스트 것에 시드·비기 설정, 양쪽 다 미리 고른 캐릭터가 있으면 실음 |
| `pick` | 캐릭터 선택(`CharacterData` 인덱스) |
| `ping` | 1초마다. 10초 동안 아무 메시지도 없으면 끊김 |
| `draw` | 뽑기 창에서 그냥 뽑음 |
| `pon` / `tsumo` / `riichi` | 선언(론은 자동이라 받는 쪽이 무시) |
| `discard` | 버린 패(손패 인덱스가 아니라 패 식별, 정렬 차이 방지) |
| `skill` | 능동 비기 id |
| `exchange` | 라운드 시작 패 교환 확정(패 식별 목록, 빈 배열이면 교환 없음) |
| `react` | 상대 론에 대한 반격 비기 사용 / 통과(`use`) |
| `nagari` | 나가리 라스트 찬스 사용 / 통과(`use`) |
| `doraBomb` | 리치 승리 때 도라 폭진 사용 / 통과(`use`) |
| `lastChanceStop` | 라스트 찬스 룰렛을 멈춘 위치(보인 장수 `shown`) |

행동 메시지는 곧 행동 로그 항목이고, 보내는 쪽이 그 행동을 적용하기 직전의 상태 해시(자리 순서의 손패·오픈 세트·HP·MP, 버림, 덱 길이, 라운드, 턴, `deck`·`fx` 스트림 호출 횟수)를 싣는다. 받는 쪽은 적용 직전의 자기 해시와 비교해 다르면 `DESYNC`로 매치를 끝낸다. 적용 조건 표는 `STRUCTURE.md` "온라인 대전".

라운드 전환은 각자 자기 결과 창을 넘기면 진행한다. 먼저 다음 라운드에 들어간 쪽의 행동은 상대 큐에서 기다린다.

## 5. 전송

`send`/`onMessage` 두 개짜리 인터페이스로 가린다.

- `BroadcastChannel`: 같은 브라우저 두 탭으로 대전(구현됨, `net/transport.js`). 서버 없이 동기화 전체를 검증하고 Playwright 테스트(`tests/online.spec.ts`)도 이것으로 돌린다.
- Cloudflare Worker + Durable Object 릴레이: 방 코드 하나로 두 소켓을 잇는다. 정적 호스팅은 그대로 두고 릴레이 주소만 상수로 둔다. 릴레이 코드는 `docs/` 밖 별도 디렉터리.
- 끊김은 매치 무효로만 처리한다. 재접속은 뒤로 미룬다.

## 6. 화면

타이틀 `ONLINE` → `CREATE`(네 글자 코드 표시, `WAITING`) / `JOIN`(캔버스 위 HTML 입력 상자에 코드) → 접속되면 각자 캐릭터 선택(`pick` 교환, 상대 초상화는 상대 선택이 오면 표시, 같은 캐릭터 허용) → 전투. 조우 씬의 스토리 대사, 컨티뉴, 세이브, 엔딩은 관여하지 않고 끝나면 타이틀로 돌아간다. 동기 어긋남·끊김은 전투 화면에 `DESYNC`·`DISCONNECT`를 띄운 뒤 타이틀로 간다. 테스트·수동 확인용 URL 진입은 `?online=host:<코드>`·`?online=join:<코드>`(`STRUCTURE.md`).

## 7. 순서

1. 자리 대칭화와 컨트롤러 분리.
2. 시드 난수와 행동 로그.
3. `BroadcastChannel` 두 탭 대전, 로비·캐릭터 선택, 상태 해시, 테스트.
4. 릴레이 작성·배포, 방 코드 UI.

1·2·3은 끝났다. 4는 `docs/IMPROVE.md`.
