# 온라인 대전 설계

두 사람이 각자의 브라우저에서 1:1로 붙는 모드. 코드 구조의 전제는 `STRUCTURE.md`, 규칙은 `../sq/RULES.md`.

## 1. 방식

양쪽 클라이언트가 각자 `BattleEngine`을 그대로 돌리고, 서로 **행동(의도)만** 주고받는다. 틱 단위 락스텝은 쓰지 않는다.

- 엔진의 논리 진행은 행동 순서로만 결정된다. 틱은 연출 대기와 생각 시간에만 쓰이므로, 리치 대답·결과 창의 확인키 넘김은 각자 알아서 하고 상대 행동은 로컬 엔진이 받을 수 있는 상태가 될 때까지 큐에 둔다.
- 각 클라이언트에서 `engine.p1` = 나, `engine.cpu` = 상대. 렌더러·씬·테스트가 두 필드를 읽는 곳은 그대로 둔다.
- 숨은 정보는 지키지 않는다. 양쪽이 전체 상태를 가지므로 개발자 도구로 상대 패를 볼 수 있다. 서버 권위 방식(서버가 덱을 쥐고 각자 패만 보냄)은 엔진을 서버에서도 돌려야 해서 범위에서 뺀다.
- 두 화면은 같아야 한다. 판·연출·배경이 양쪽에서 동일하도록 전투 안의 무작위는 전부 공유 시드 난수에서 나온다(3절). 예외는 상대 캐릭터만 하는 대사(버림 대사, 펑 대답)로, 각자 자기 상대의 말풍선만 본다. 난수 소비는 양쪽이 같게 하고 보여 주기만 가른다(사용자 결정).

## 2. 자리 대칭화

구현됨(`STRUCTURE.md` "자리와 컨트롤러"). 엔진은 자리 무관 적용 함수(`drawFor`·`discardFor`·`declarePon`·`declareRiichi`·`declareTsumo`·`declareRon`·`confirmTileExchange`·`activateLastChance`)만 가지고, 자리마다 컨트롤러(`logic/seatControllers.js`의 `HumanController`·`AIController`)가 결정을 내려 그 함수를 부른다.

- 컨트롤러가 답하는 지점: 뽑기 창(펑·그냥 뽑기), 차례(리치·쯔모·비기·버림), 내 론에 대한 반격 비기(초발도·론 교환) 응답, 라운드 시작 패 교환, 나가리의 라스트 찬스, 룰렛 자동 정지 여부. 론은 리치 중 화료패가 나오면 규칙상 자동이라 결정이 아니고, 양쪽 엔진이 스스로 건다. 따라서 4절의 `ron` 메시지는 필요 없다.
- AI 컨트롤러는 옛 코드를 그대로 옮겨 동기로 답하고, 생각 시간은 `update` 훅이 `engine.timer`로 잰다.
- 네트워크 컨트롤러(`net/netController.js`)는 모든 통지에서 결정하지 않고 답을 받을 `resolve`만 보관하며, 메시지가 오면 같은 적용 함수를 부른다. 상대 자리는 `STATE_CPU_TURN` 안의 `cpuPhase`(`draw` → `turn`)로 어느 메시지를 기다리는지 안다. 엔진은 상태와 무관하게 매 틱 컨트롤러의 `poll`을 불러 큐를 비울 기회를 준다.
- 순서 의존 로직은 자리 번호(호스트 0, 게스트 1, `engine.localSeat`) 기준이다: 배패·라운드 시작 셋업은 자리 1부터, 선공 `firstSeat`, 라스트 찬스는 자리 0부터. 각 클라이언트에서 `engine.p1`은 여전히 자기이고 `whoAt(seat)`이 자리와 `P1`/`CPU`를 잇는다.
- 승리 때 도라 폭진은 `onDoraBomb` 통지로 묻고 답을 `doraBomb` 메시지로 보낸다. 상대 론 교환 뒤 어느 패를 다시 버릴지는 자기 차례의 `discard`로 온다. 룰렛 자동 정지 위치는 `rouletteStopAt` 통지이고 네트워크 컨트롤러는 `lastChanceStop` 메시지가 올 때까지 멈추지 않는다.

## 3. 무작위

전투 중 `Math.random`을 쓰지 않고 `engine.rng`(시드 난수)만 쓴다. 호스트가 매치 시작 때 시드를 보낸다. 용도별 스트림으로 나눠, 한 용도의 소비 순서가 어긋나도 다른 용도가 흔들리지 않게 한다.

- `deck`: 셔플, 도라·우라도라, 선공, `luck` 드로우 편향. 뽑기는 양쪽에서 같은 논리 순서로 일어난다.
- `fx`: 전투 배경, 대사 발동 확률과 대사 선택, 도라 룰렛 회전 수. 대사는 버림·펑·비기·승패 같은 논리 이벤트에서만 발동하므로 양쪽 소비 순서가 같아야 한다. 그래서 `fx` 소비는 자리에 무관하게 한다: 어느 자리가 버리든 대사 확률을 굴리고 대사까지 고르되, 말풍선은 그 자리가 상대일 때만 띄운다(펑 대답도 같은 규칙). 상태 해시에 `fx` 소비 횟수를 넣어 어긋남을 잡는다.
- `ai`: AI 판단 전부(비기 사용·반응, 론 교환에서 되가져올 패, 라운드 시작 교환, 라스트 찬스 자동 정지 위치, 버림·리치·펑 확률). 사람·원격 상대는 쓰지 않으므로 온라인에서는 동기화 대상이 아니다. 시드만으로 오프라인 경기를 재현하려고 같은 체계에 둔다.

구현은 `STRUCTURE.md` "난수". 시드는 `BattleEngine.init`의 `data.seed`(32비트)로 받아 `engine.seed`에 남는다. 행동은 `engine.actionLog`에 `{ round, who, type, ...payload }`로 쌓인다(버린 패는 `{ type, color }`).

메시지는 의도만 싣고 결과를 싣지 않는다. 사람이 키로 멈추는 라스트 찬스 룰렛만 정지 위치가 의도다.

온라인에서 끄는 것: easy 드로우 어시스트. 두는 것: `luck`(캐릭터 특성). 비기 사용 여부는 방을 만든 호스트가 정하고 방 단위로 고정된다(재대전도 같은 값, 기본은 켬).

시드와 행동 로그를 저장하면 그대로 리플레이가 된다. 1차 범위에는 넣지 않는다.

초상화 눈 깜빡임은 프레임 기반 애니메이션이라 시드를 줘도 주사율에 따라 어긋난다. 판에 영향이 없으므로 로컬 그대로 둔다.

## 4. 메시지

행동한 쪽이 보내고, 자리 기준(보낸 사람 자리)이다.

| 메시지 | 내용 |
|---|---|
| `hello` | 접속 인사. 호스트 것에 시드와 비기 사용 여부(`skills`), 양쪽 다 미리 고른 캐릭터가 있으면 실음 |
| `pick` | 캐릭터 선택(`CharacterData` 인덱스) |
| `ping` | 1초마다. 10초 동안 아무 메시지도 없으면 끊김 |
| `bye` | 방을 나갈 때(탭을 닫을 때 포함). 받으면 기다리지 않고 상대가 나간 것으로 처리 |
| `rematch` | 매치가 끝난 뒤 `다시 대전`을 누름 |
| `rematchStart` | 호스트가 양쪽의 `rematch`를 확인하고 보냄. 새 시드를 싣고, 양쪽이 캐릭터 선택부터 다시 시작 |
| `draw` | 뽑기 창에서 그냥 뽑음 |
| `pon` / `tsumo` / `riichi` | 선언(론은 자동이라 받는 쪽이 무시) |
| `riichiCancel` | 리치 패를 버리기 전 리치 취소 |
| `discard` | 버린 패(손패 인덱스가 아니라 패 식별, 정렬 차이 방지) |
| `skill` | 능동 비기 id |
| `exchange` | 라운드 시작 패 교환 확정(패 식별 목록, 빈 배열이면 교환 없음) |
| `react` | 상대 론에 대한 반격 비기 사용 / 통과(`use`) |
| `nagari` | 나가리 라스트 찬스 사용 / 통과(`use`) |
| `doraBomb` | 리치 승리 때 도라 폭진 사용 / 통과(`use`) |
| `lastChanceStop` | 라스트 찬스 룰렛을 멈춘 위치(보인 장수 `shown`) |
| `confirm` | 결과 창(승·패·나가리)을 넘김. 몇 번째 결과 창인지(`win`)를 싣는다 |

행동 메시지는 곧 행동 로그 항목이고, 보내는 쪽이 그 행동을 적용하기 직전의 상태 해시(자리 순서의 손패·오픈 세트·HP·MP, 버림, 덱 길이, 라운드, 턴, `deck`·`fx` 스트림 호출 횟수)를 싣는다. 받는 쪽은 적용 직전의 자기 해시와 비교해 다르면 동기 어긋남으로 매치를 끝낸다. 적용 조건 표는 `STRUCTURE.md` "온라인 대전".

결과 창은 어느 한쪽이 넘기면 `confirm`이 나가 양쪽이 같이 넘어간다. 아직 결과 창에 오지 못한 쪽은 큐에서 기다렸다가 도착하면 넘기고, 양쪽이 거의 동시에 눌러 뒤늦게 도착한 `confirm`은 이미 지난 결과 창 것이므로 버린다. 그다음 라운드의 행동도 상대가 따라올 때까지 큐에서 기다린다.

## 5. 전송

`send`/`onMessage` 두 개짜리 인터페이스로 가린다.

- `BroadcastChannel`: 같은 브라우저 두 탭으로 대전(구현됨, `net/transport.js`). 서버 없이 동기화 전체를 검증하고 Playwright 테스트(`tests/online-local.spec.ts`)도 이것으로 돌린다.
- Cloudflare Worker + Durable Object 릴레이(구현됨, `relay/`와 `net/transport.js`의 `WebSocketTransport`): 방 코드 하나로 두 소켓을 잇는다. 정적 호스팅은 그대로 두고 릴레이 주소만 `BattleConfig.ONLINE.RELAY_URL`에 둔다. 릴레이 코드는 `docs/` 밖 별도 디렉터리.
- 선택 규칙: `vs.html?transport=local`이면 항상 `BroadcastChannel`. 아니면 `?relay=주소`(테스트·시험용)가 있으면 그것, 없으면 `RELAY_URL`이 있을 때 WebSocket, 비어 있으면 `BroadcastChannel`.
- 릴레이 경로의 접속·끊김: 릴레이의 `peer joined`는 전송층이 처리하고 `Match`는 그때부터 `hello`를 보낸다(상대가 없을 때 보낸 것은 서버가 버리므로). `peer left`는 `bye`와 같은 경로(`left`), 자리가 찼을 때 릴레이가 보내는 `peer full`은 `full`(`방이 가득 찼습니다`), 소켓 `close`·`error`와 접속 거부(코드 오류 400 포함)는 `disconnect`로 처리한다. 소켓이 끊김을 알려 주므로 `ping`과 10초 타임아웃은 쓰지 않는다(`BroadcastChannel` 경로에만 남는다).
- 방 코드는 5자(I·O 제외 대문자)다. 쾌진극의 5자 패스워드 관례에 맞췄다.
- 끊김은 매치 무효로만 처리한다. 재접속은 뒤로 미룬다.

## 6. 화면

온라인 대전의 공식 이름은 `VS MODE`이고, 게임 캔버스의 타이틀·메뉴를 거치지 않고 별도 페이지 `vs.html`에서 시작한다. `index.html?mode=vs`는 게임을 띄우지 않고 나머지 파라미터를 그대로 두고 `vs.html`로 보낸다. 상단바에는 소리·역 계산기·게임패드·전체 화면만 있고 난이도·비기 토글은 없다(난이도 없음). 역 계산기는 데스크톱 폭에서 켜진 채로 시작한다. 비기는 시작 화면에서 방을 만들 때만 고르고(퀵 매치는 항상 켬), 게스트는 호스트의 `hello`에 실린 값을 따른다. 전투가 시작될 때 양쪽이 그 값으로 `BattleConfig.RULES.SKILLS_ENABLED`를 맞춘다. 대기 화면에는 고른 값이 `비기 켜짐`/`비기 꺼짐` 글자로 나온다(게스트는 호스트의 `hello`를 받기 전까지 모르므로 호스트가 없을 때는 비어 있다). 페이지는 검색 엔진에 올리지 않는다(`noindex`, 사이트맵 제외).

로비는 캔버스 위에 덮는 HTML 패널이다. 상태는 넷이다.

- **시작**: `VS MODE` 글자 아래 두 묶음. 줄마다 왼쪽에 설명·입력, 오른쪽 끝에 같은 너비의 노란 버튼을 두어 세 버튼이 한 세로줄로 맞는다. 묶음 제목은 왼쪽 정렬. 제목 `되는 대로 대전` 아래 줄은 인원과 퀵 매치 버튼 `참가`. 인원은 접속·대기 아이콘(`ui/presence.png`의 사람과 모래시계) 옆 숫자만이고, 접속은 vs 페이지를 열어 둔 사람 수로 나를 포함, 대기는 퀵 매치를 누르고 기다리는 사람 수다. 로비 서버에 연결되지 않았으면 인원이 없고, 있든 없든 버튼 자리는 그대로다. 구분선, 제목 `방 만들어 대전` 아래 `비기` 글자와 패 모양 켬/끔 토글(`ui/pai_onoff.png`의 왼쪽 반이 켬, 오른쪽 반이 끔, 기본 켬)과 `방 만들기`, 옅은 구분선, 코드 입력 상자(대문자 다섯 글자)와 `참가`. 초대 링크 `vs.html?room=코드`로 열면 입력 없이 바로 참가한다. `?transport=local`이면 첫 묶음이 없다.
- **대기**: 코드를 크게 보이고, 호스트만 `코드 복사`·`바로 입장 링크 복사` 두 버튼을 둔다(복사하면 토스트 `코드를 복사했습니다`·`바로 입장 링크를 복사했습니다`). 그 아래 `상대를 기다리는 중`(뒤에 점이 하나씩 늘어난다)과 `취소`. 게스트는 코드와 같은 문구. 대기 화면에 10분(`BattleConfig.ONLINE.WAIT_SEC`) 머물면 방을 닫고 시작 화면으로 돌아가며 토스트 `상대가 오지 않아 방을 닫았습니다`를 띄우고, 30초 전(`WAIT_WARN_SEC`)에 `30초 뒤 방이 닫힙니다`를 한 번 띄운다. 남은 시간은 화면에 따로 보이지 않는다. 릴레이 경로에 `ping`이 없어 오래 조용한 소켓이 끊길 수 있는데, 대기가 이 시간으로 끝나므로 따로 막지 않는다.
- **퀵 매치 대기**: `비기 켜짐`, `상대를 기다리는 중`, `취소`. 코드는 보이지 않는다. 짝이 지어지면 받은 코드로 방에 들어가 대기와 같이 이어진다. 대기 제한 시간과 토스트는 대기와 같다. 로비 연결이 끊기면 시작 화면으로 돌아가 `연결이 끊어졌습니다`를 띄운다.
- **매치 끝**: 같은 방을 유지한 채 `WIN`/`LOSE` 글자, 라운드 목록, `다시 대전`, `나가기`. 한쪽만 누르면 그쪽은 버튼 자리에 `상대를 기다리는 중`. 둘 다 누르면 호스트가 새 시드를 보내고 양쪽이 캐릭터 선택부터 다시 간다.

접속되면 패널이 닫히고 각자 캐릭터 선택(`pick` 교환, 상대 초상화는 상대 선택이 오면 표시, 같은 캐릭터 허용). 눈썹개는 싱글에서 해금한 이력(세이브)이 있는 쪽만 고를 수 있고, 상대가 해금한 눈썹개를 골라 왔으면 내 해금 여부와 무관하게 초상화·이름·대사를 일반 캐릭터처럼 그린다(오프라인 CPU전의 실루엣·`???` 표기는 온라인에서만 끈다) → 전투 → 매치 끝 패널. 조우 씬의 스토리 대사, 컨티뉴, 세이브, 엔딩은 관여하지 않는다. 로비·캐릭터 선택·매치 끝 패널에서 상대가 나가면(`bye`) 시작 상태로 돌아가고 `상대가 나갔습니다`를, 응답이 끊기면 `연결이 끊어졌습니다`를 알린다. 캐릭터 선택에서 ESC는 방을 나간다.

**상태 영역**: 게임 컨테이너 왼쪽 위(캐릭터 선택 제목 띠 아래)에 테두리 없이 모서리를 둥글린 반투명 검정 토스트 하나(`#online-status`)를 두고, 로비 패널보다 위에 그린다. 문구가 바뀔 때 나타났다가 잠시 뒤 흐려지고, 로비 패널이 떠 있을 때도 같은 요소를 쓴다. 문구는 전부 `OnlineLobby.TOASTS` 한 표에 있다: `상대가 들어왔습니다`, `상대가 나갔습니다`, `상대가 캐릭터를 고르는 중`(내가 먼저 골랐을 때), `상대가 다시 대전을 원합니다`, `상대가 나가서 CPU가 이어받습니다`, `방이 가득 찼습니다`, `연결이 끊어졌습니다`, `동기가 어긋났습니다`, `코드를 복사했습니다`, `바로 입장 링크를 복사했습니다`, `30초 뒤 방이 닫힙니다`, `상대가 오지 않아 방을 닫았습니다`.

**제한 시간**: 온라인 전투에서만 돈다. 시간이 다한 쪽이 스스로 기본 행동을 하고 그 행동이 평소처럼 메시지로 나간다. 상대에게 강제하는 것은 없고, 양쪽 화면이 같은 카운트다운을 그리되 판에는 로컬 행동만 영향을 준다. 입력이 열리는 시점부터 센다.

| 대상 | 다 되면 |
|---|---|
| 뽑기 창 | 그냥 뽑음 |
| 내 차례 | 방금 뽑은(맨 오른쪽) 패를 버림. 비기 메뉴가 열려 있으면 닫고 버림. 리치 중에는 기존 자동 버림 |
| 라운드 시작 패 교환 | 교환 없이 확정 |
| 확인창(반격 비기·라스트 찬스·도라 폭진) | 안 씀 |
| 라스트 찬스 룰렛 | 그 자리에서 멈춤 |
| 결과 창 | 넘김(`confirm`) |

길이는 `BattleConfig.ONLINE`에 초 단위로 있다. 숫자는 비트맵 숫자로, 내 차례·뽑기 창은 내 손패 줄 왼쪽, 상대 차례는 상대 손패 줄 왼쪽에 그린다. 제한 시간은 두 가지뿐이다: 버림(`DISCARD_SEC`)과 그 밖의 선택(뽑기 창·확인창·패 교환·룰렛·결과 창, `CHOICE_SEC`). 버림은 금색 `ui/number_gold.png` 숫자 위에 노란 글자 `버리기까지`(강조), 선택은 TURN·ROUND와 같은 은색 `ui/number.png` 위에 흰 글자 `선택까지`를 붙여 색과 말이 같은 두 갈래로 나뉜다(`BattleConfig.ONLINE.CLOCK`). 리치 자동 진행, 자동 테스트, 튜토리얼에서는 끈다.

**CPU 인계**: 전투 도중 상대의 `bye`·끊김·동기 어긋남은 매치를 무효로 하지 않는다. 상대 자리 컨트롤러를 `NetController`에서 `AIController`로 바꿔 판을 그대로 잇고(보통 난이도의 실력), 상대에게 답을 기다리던 확인창·교환·룰렛은 AI가 대신 답한다. 인계 뒤에는 메시지 수신·전송을 멈추고 제한 시간과 카운트다운을 끈다. 눈썹개 실루엣은 켜지 않는다. 매치가 끝나면 결과 패널에 `다시 대전` 없이 `나가기`만 보인다. 동기 어긋남은 양쪽 판이 이미 다르므로 끊김과 같이 각자 CPU와 끝낸다. 전투가 아닌 단계(로비·캐릭터 선택·매치 끝 패널)의 이탈은 인계 없이 시작 상태로 돌아간다.

**화면 구성**: 로비 패널은 상태 객체 하나를 `OnlineLobby.render(state)`가 그린다. 상태는 `view`(`start`·`wait`·`ended`·`hidden`), `code`, `role`(`host`·`guest`), `result`(`win`·`lose`), `rounds`, `canRematch`, `rematch`(`idle`·`waiting`)이고, 매치 이벤트는 상태만 바꾸고 `render`를 부른다. 토스트는 상태와 별개다. 무대 배경은 `assets/bg/STAFFBAK.png`이고 창은 캔버스 가운데 하나, 프레임 PNG 여덟 장을 CSS 배경으로 640 기준 14px에 그린다. 안쪽은 게임 창과 같은 검정 60%. `VS MODE`(노랑 줄)와 `WIN`/`LOSE`(주황 줄)는 `ui/alphabet.png`를 CSS 스프라이트로 그린다(글자 사이 추가 간격 없음, 띄어쓰기는 반 칸). 크기는 컨테이너 폭 기준 단위 하나(`--ol-u`, 640 기준 1px)에서 나와 모바일에서도 같이 줄어든다. 색·크기 토큰은 `haiyuki.css`의 VS MODE 절 `--ol-*`에 있고, 페이지 토큰(`--text-2`, `--surface-2`, `--stage-btn-border`, `--stage-text`, `--stage-text-2`)을 가리키며, 역 계산기 값(`--frame`·`--gold`·`--yellow`)과 게임 창 값(`--game-window-bg`·`--game-select-text`)은 같은 이름으로 그 절에서 정의한다. 버튼은 역 계산기 양각 모양이다(주 버튼 금색, `취소`·`나가기`는 흰색).

`vs.html?preview=이름`은 매치 없이 그 이름의 가짜 상태를 그린다(`start`, `start-failed`, `wait-host`, `wait-guest`, `ended-win`, `ended-waiting`, `ended-peer-rematch`, `ended-takeover`, `ended-long`). 토스트가 있는 상태는 토스트도 띄우고, 버튼은 동작하지 않는다. 화면 회귀 스냅샷이 이것을 쓴다.

**라운드 기록**: 엔진은 라운드마다 `roundHistory`에 항목을 남긴다(싱글 플레이에도 남지만 화면은 바뀌지 않는다). 승리는 결과 창 값이 정해지는 지점, 나가리는 나가리 시퀀스 시작에서 기록하고, 같은 라운드에 라스트 찬스로 승리하면 나가리 항목을 승리 항목이 대체한다.

| 항목 | 내용 |
|---|---|
| `round` | 라운드 번호 |
| `winner` | `P1`·`CPU`·`null`(나가리) |
| `how` | `tsumo`·`ron`·`nagari` |
| `yaku` | 역 이름, 나가리는 `null` |
| `baseScore` · `damage` | 보정 전 점수 · 최종 데미지 |
| `bonuses` | 결과 창의 보너스 `details` 그대로 |
| `mods` | 적용된 비기 id(`CRITICAL`·`WATER_MIRROR`·`DORA_BOMB`) |
| `open` | 승자의 오픈 여부 |
| `riichi` · `uraDora` | 양쪽 리치 여부 · 공개된 뒷도라 종류 |
| `tenpai` · `nagariBy` | 나가리의 양쪽 텐파이 여부 · `deck`(패산 소진)·`turns`(턴 초과) |
| `lastChance` · `counter` | 라스트 찬스 `{who, hit}` · 반격 비기 `{id, ok}`, 없으면 `null` |
| `turns` · `hp` · `firstSeat` | 턴 수 · 라운드 뒤 양쪽 HP · 선 자리 |

`OnlineMatch.finish`의 `summary`에 `rounds`(이 매치의 `roundHistory`)와 `chars`(내 캐릭터·상대 캐릭터 인덱스)가 더해진다. 매치 끝 화면의 목록은 한 줄에 네 칸만 보인다: `R{n}` · `승`/`패`/`무승부` · 역 이름(무승부면 `텐파이`/`노텐` 나/상대 순) · 최종 데미지(`-2400`). 역 칸은 한 줄 고정이고 넘치면 역 이름만 말줄임표로 줄이며 보너스(` · 도라 N`, ` · 텐호`, ` · 치호`, ` · 렌호`, ` · 해저`, ` · 하저`: 보너스 이름에서 `보너스`를 뗀 것)와 `텐파이`/`노텐`은 항상 보이고, 목록은 7줄 높이까지 보이고 넘치면 목록 안에서 스크롤하며 처음에는 마지막 줄이 보인다. 재대전이면 새 매치의 것만 보인다.

## 7. 순서

1. 자리 대칭화와 컨트롤러 분리.
2. 시드 난수와 행동 로그.
3. `BroadcastChannel` 두 탭 대전, 로비·캐릭터 선택, 상태 해시, 테스트.
4. 릴레이 작성·배포(WebSocket 전송층).

1·2·3·4 모두 끝났다. 릴레이는 `haiyuki-relay.flvrdoyster.workers.dev`에 배포되어 있고 주소는 `BattleConfig.ONLINE.RELAY_URL`에 있다. 재접속은 하지 않는다(끊기면 남은 쪽이 CPU와 끝낸다). 퀵 매치는 릴레이의 로비 Durable Object가 짝을 지어 방 코드를 준다(`relay/README.md`).
