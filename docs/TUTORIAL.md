# 튜토리얼 설계 (초안)

## 1. 정한 것
- 방식: 게임 안에서 정해진 패로 직접 해 보는 튜토리얼. 역 30종·비기·도라·보너스는 가르치지 않고 해설서(툴바 "역 일람", `char.html`)로 넘긴다.
- 크기: 작게. 새 화면은 나레이션 상자 하나뿐이고, 나머지는 기존 전투 화면과 엔진을 그대로 쓴다.
- 진입점: 타이틀 메뉴 항목 `TUTORIAL`.
- 범위: 레슨 1~4를 한 번에 이어서 진행한다.
- 캐릭터: 플레이어·상대 모두 무작위(서로 다른 캐릭터, 눈썹개 제외). 레슨 패는 캐릭터와 무관하게 성립한다.
- 안내: 캐릭터가 아니라 중립 대화 상자의 나레이션.
- 문구: 나레이션은 `js/data/tutorialData.js`의 레슨 `script`에서 고친다.
- 본편과 완전히 분리: 매치 진행·해금·클리어 기록·이어하기 횟수에 아무 영향 없음, 저장하지 않음. HP는 튜토리얼 전투 안에서만 깎인다.

## 2. 흐름
타이틀 → 튜토리얼 → 레슨 1(쯔모) → 레슨 2(리치) → 레슨 3(펑) → 레슨 4(론) → 타이틀.

라운드는 네 번이다. 레슨 1이 쯔모로 끝나면 라운드가 끝나므로 한 라운드에 다 담을 수는 없다. 레슨 사이에는 메뉴 없이 나레이션 한 번 뒤 다음 레슨 판을 바로 돌린다. 도중에 ESC로 메뉴를 열면 "타이틀로"만 있으면 된다.

리치·아가리를 해야 하는 차례에는 선언 전까지 모든 패를 버릴 수 없게 막는다. 펑만은 넘길 수 있어서(패 가져오기), 펑을 넘기면 나레이션을 한 번 보이고 **그 레슨을 처음부터 다시** 시작한다. 단계별 되감기는 만들지 않는다.

## 3. 구현에 필요한 것 (최소)
엔진에 `tutorial` 플래그 하나를 두고 아래 지점에서만 갈라진다.

1. **판 준비**(`startRound`): 셔플 대신 레슨 데이터로 플레이어 배패 11장, 플레이어 뽑기 순서, CPU 뽑기 순서를 채운다. 도라·우라도라도 레슨 데이터로 고정한다. 레슨 1만 도라 보너스를 보이고(화린 3장, 1200), 나머지는 화료 패와 겹치지 않는 패로 해 보너스가 끼지 않게 한다. 배경은 무작위여도 상관없다.
2. **무작위 끄기**: easy 드로우 어시스트, `cpuLuck`을 쓰지 않는다. 비기는 툴바 "비기 끄기"와 같은 상태로 둔다.
3. **CPU**: 뽑은 패를 그대로 버린다. 쯔모·리치·펑·론·비기를 하지 않는다. CPU의 전투 대사(버릴 때 무작위 대사, 플레이어 리치 때 걱정 대사 등 `triggerDialogue`)도 끈다. 나레이션과 겹치지 않게 하기 위해서다. 그러면 CPU 버림 순서 = CPU 뽑기 순서라서 레슨 데이터가 단순해지고, CPU 손패 11장은 아무 패나 채우면 된다.
4. **버릴 수 있는 패 제한**: 레슨 단계마다 버릴 수 있는 패 한 종류만 받는다. 리치 선언 때 쓰는 "고를 수 없는 패 어둡게" 표시를 그대로 쓴다.
5. **나레이션 상자**: 화면 아래 중립 상자. 떠 있는 동안 엔진 진행을 멈추고, Space·클릭·터치로 넘긴다. 띄우는 시점은 "레슨 n, 턴 t, 플레이어 차례 시작/버린 뒤/펑 가능/론 가능/승리" 정도의 조건으로 레슨 데이터에 적는다.
6. **라운드 끝**: 승리 연출·결과 화면·데미지는 본편과 같다(네 레슨 합계 16800으로 상대 HP 12800이 마지막 론에서 0이 된다). `matchOver`로 가지 않고 다음 레슨(또는 타이틀)으로 간다.
7. **타이틀 메뉴**: 세 번째 항목 RESET 자리에 `TUTORIAL`을 넣는다(비트맵 알파벳). 기록 초기화는 UI에서 빼고 콘솔 `resetSave()`로만 남긴다.
8. **테스트**: 레슨 데이터의 각 단계 손패가 "텐파이(대기 역 ○○)/역 ○○ 성립"인지 단언하는 spec 하나. 판정 규칙이 바뀌면 여기서 먼저 깨진다.

만들지 않는 것: 손패 칸 강조 테두리, 단계별 되감기, 레슨 선택 화면, 진행 저장, 비기·나가리 레슨.

## 4. 레슨 데이터

모든 손패는 `yakuLogic.js`로 판정을 확인했다. 눈썹개를 포함한 7명 모두 같은 역·점수가 나와 캐릭터를 무작위로 골라도 된다. 패 표기는 `paiData.js` id. 양쪽 버림 수는 플레이어 n턴 버림이 2n−1, CPU n턴 버림이 2n이다.

역은 가장 기본인 삼도립, 중간 점수 하나, 특이한 것 하나로 고른다: 삼도립 2400(레슨 1·2) → 적일색 4800(펑으로 3600) → 취호전 7200.

CPU 뽑기(=버림) 패는 플레이어가 2장 이상 가진 패를 피한다. 그래야 의도하지 않은 펑 확인이 뜨지 않는다.

### 레슨 1 — 뽑고 버리고 쯔모 (삼도립 2400)
| 턴 | 플레이어 | CPU 버림 | 상태 |
|---|---|---|---|
| 배패 | `smash×3 yuri×3 pet×3 mayu_red×1 mayu_blue×1` | | |
| 1 | 뽑기 `fari`, 버림 `mayu_red`만 허용 | `wand` | |
| 2 | 뽑기 `fari`, 버림 `mayu_blue`만 허용 | `sword` | 텐파이, 대기 역: 삼도립 |
| 3 | 뽑기 `fari` → 쯔모 | | 삼도립 2400 + 도라 보너스 x3 1200 |

1턴에는 텐파이가 아니다(처음 버리는 법을 배우는 차례). 2턴에 텐파이가 되지만 리치 버튼은 띄우지 않는다. 닫힌 손패가 텐파이면 리치 조건이 되므로 패 구성으로는 피할 수 없고, 리치를 가르치는 레슨(`needRiichi`)이 아니면 튜토리얼이 리치 선언을 막는다.

### 레슨 2 — 리치 (삼도립 2400)
레슨 1과 같은 배패·뽑기·CPU 버림. 같은 텐파이에서 쯔모를 기다리는 대신 리치를 걸고 기다려도 된다는 것을 보인다.

| 턴 | 플레이어 | CPU 버림 | 상태 |
|---|---|---|---|
| 배패 | `smash×3 yuri×3 pet×3 mayu_red×1 mayu_blue×1` | | |
| 1 | 뽑기 `fari`, 버림 `mayu_red`만 허용 | `wand` | |
| 2 | 뽑기 `fari`, 리치 선언, 버림 `mayu_blue` | `sword` | 리치, 대기 역: 삼도립 |
| 3 | 뽑기 `punch` → 자동 버림 | `mayu_purple` | |
| 4 | 뽑기 `mayu_yellow` → 자동 버림 | `rin` | |
| 5 | 뽑기 `fari` → 자동 쯔모 | | 삼도립 2400, 우라도라 공개 |

리치 직후가 아니라 두 번 받고 버린 뒤에 나야 리치를 걸고 기다리는 모습이 보인다. 이 사이 CPU 버림은 대기 패(`fari`)를 피한다(리치 중이라 론이 자동으로 나간다).

1턴에는 리치를 걸 수 없으므로 리치 없이 버려도 실패가 아니다. 리치가 가능한 2턴에 리치 없이 버리면 실패.

### 레슨 3 — 펑과 그 대가 (적일색 4800 → 3600)
| 턴 | 플레이어 | CPU 버림 | 상태 |
|---|---|---|---|
| 배패 | `ataho×2 rin×3 punch×3 mayu_purple×2 sword×1` | | |
| 1 | 뽑기 `wand`, 버림 `sword`만 허용 | `mayu_yellow` | |
| 2 | 뽑기 `pet`, 버림 `pet`만 허용 | `ataho` → 펑 | 버림 수 4, 펑 가능 구간 |
| (펑) | `ataho×3` 오픈, 뽑지 않고 버림 `wand`만 허용 | `mayu_blue` | 텐파이(오픈), 대기 역: 적일색 |
| 3 | 뽑기 `mayu_purple` → 쯔모 | | 적일색 4800 → 오픈이라 3600 |

빨강 3종류(아타호·린샹·주먹)를 3장씩과 보라 눈썹개 3장. 일색은 모은 색에 따라 이름이 적·황·청일색으로 바뀌는 것도 보여 줄 수 있다. 1·2턴의 12장은 어느 패를 버려도 텐파이가 아니라 리치 버튼이 뜨지 않는다.

펑을 1턴이 아니라 2턴에 시킨다. 해설서가 "1턴 째, 20턴 째에는 펑을 할 수 없습니다"라고 쓰고 있어서, 1턴 펑을 보여 주면 해설서와 어긋나 보인다.

"CPU가 대기 패를 버려도 론 버튼이 안 뜬다"는 직접 보여 주지 않는다. 대기 패를 2장 쥐고 있어 그때 펑 확인이 떠 버리기 때문이다(3장 묶음 역은 대기 패가 늘 쌍이다). 나레이션으로만 말하고, 직접 보여 주는 건 레슨 4의 론으로 대신한다.

### 레슨 4 — 론 (취호전 7200)
| 턴 | 플레이어 | CPU 버림 | 상태 |
|---|---|---|---|
| 배패 | `ataho×4 rin×4 smash×2 yuri×1` | | |
| 1 | 뽑기 `smash`, 리치 선언, 버림 `yuri`(텐파이를 유지하는 유일한 패라 엔진이 나머지를 어둡게 함) | `mayu_yellow` | 리치, 대기 역: 취호전 |
| 2 | 뽑기 `mayu_red` → 자동 버림 | `smash` → 론 | 취호전 7200 |

취호전의 세 사람(아타호·린샹·스마슈)을 4장씩 모으는 역. 4장 묶음이라 펑을 하면 만들 수 없는 닫힌 패 전용 역이다. 레슨 3과 이어서 "펑하면 이런 역을 잃는다"를 말할 수 있다. 리치는 레슨 2에서 배웠으므로 나레이션은 론에 집중한다.
