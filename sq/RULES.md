# 환세패유기 Windows판 규칙·AI (`haiyuki.exe` 역분석)

대상: `haiyuki.exe`(이미지 베이스 0x400000)의 `0x20` 클래스 내장 루틴 44개와 그들이 부르는 함수, 그리고 `usamain.sq`의 호출 순서. 주소는 모두 가상주소. 디컴파일은 `extracted/sq/ghidra/decomp/all.c`, `handlers.c`(ignore 폴더)를 쓰고, 역 판정 함수 26개(0x421c70~0x424600)는 Ghidra에서 함수를 새로 만들어 디컴파일했다. 확신도 표기: **확정** = 코드를 끝까지 읽음, **추정** = 일부만 읽었거나 호출 문맥에서 판단.

표기: `glob[n]` = 스크립트 전역 배열 `DAT_00476100 + 4n`. 플레이어 0 = 사람, 1 = CPU(스크립트가 `ctx.res`로 넘기는 플레이어 번호).

## 2. 데이터 구조

### 2.1 패산·전역
- `DAT_004756e0`: u32[0x75=117], 값 = 종류 번호 0..12. 종류마다 9장(13×9). 도라용 패는 따로 빼지 않는다. (418bd0)
- `DAT_004760f8`: 다음에 뽑을 위치. 배패 후 22, 뽑을 때마다 +1. 되감김(순환)은 없다. 최대 22+40=62. 0x75로 되감는 코드는 엿보기 표시(0a)에만 있다.
- `DAT_00476f40[13]`: 종류별로 아직 뽑히지 않은 수.
- `glob[140]`(`DAT_00476330`): 지금까지 버려진 패 수 0..40. 스크립트가 버릴 때마다 +1(usamain E11, E12). 40이 되면 나가리(usamain E13의 `glob140 == 40`).
- `glob[142]`,`glob[143]`(`DAT_00476338`,`3c`): 플레이어 0,1의 리치 표시. 0xff = 리치 아님, 아니면 선언 시점의 버림 수(1b).
- `glob[148]`,`glob[149]`(`DAT_00476350`,`54`): 도라 종류 + 27. 116(0x74) = 없음. `glob[148]`은 배패 후 27..39를 도는 룰렛으로 정해지고(usamain E3~E5), `glob[149]`(숨은 도라, 웹의 우라도라)는 승리 처리에서 승자가 리치일 때만 `rand(13)+27`로 정해진다(usamain E27→E28: CPU 승리, E59→E60: 사람 승리. 진입 검사가 승자 자신의 `glob[143]`/`glob[142] == 0xff`면 건너뜀). 판 시작(usamain E2, 0x4e8)에 116으로 지운다. 이 흐름에서 린샹 B(도라 폭진)를 쓰면 E28·E60의 무작위 설정을 지나치고 스킬이 손패 최다 종류로 정한다(22).
- `glob[202]`,`glob[203]`: HP(초기 12800). `glob[204]`,`glob[205]`: MP(초기 100). usamain 시작부(0x2f8~0x338)에서 대입. `DAT_004762ec`: 승리 점수(=데미지), `glob[123]`: 적용 데미지(기본 1000).
- `DAT_00476420`,`DAT_00476424`: 플레이어 0,1의 캐릭터 번호 0..6(6절). `DAT_004765e8`(=`glob[314]`): 스테이지 번호, 시작 1(415750, startup.sq가 증가; 7절).

### 2.2 플레이어 구조체 (간격 0x4d dword = 0x134 바이트, 플레이어 0 = 0x476a60, 1 = 0x476b94)

| 0..11 | 손패 칸(종류 번호, 빈칸 0xff). 오픈 세트가 m개이면 앞의 12-3m칸만 쓰고 마지막 쓰는 칸(11-3m)이 뽑은 패 칸 | 418c70, 419f30 |
| 12..24 | `A[13]`: 그 플레이어가 아는 종류별 수(자기 손패 + 자기 버림 + 상대 버림 + 상대 펑). 뽑기와 배패에서 +1, 상대 버림에서 +1, 상대가 펑하면 +2. 미확인 수 = 9-A | 418c70, 41a120, 41a1b0, 421320 |

HP·MP·리치 상태는 구조체가 아니라 위 전역(`glob[...]`)에 있다. 손패 크기는 항상 12-3m이고 평가·역 판정은 이 12-3m칸 + 오픈 세트(종류당 3장)를 합쳐 항상 12장으로 한다.

### 2.3 역 배열
- 정의 `DAT_00474260`: 역당 0xf dword. +0 이름 포인터, +4 설명 포인터, +8 점수, +0xc 패 번호 12개. 역 수 `DAT_0047868c`=30. (41a3f0)
- 판정 결과 `DAT_004770a0`: 역당 0x13 dword. [0] 성립, [1] 1장 부족(텐파이), [2] 부족한 장수(성립이면 0), [3..14] 손패 칸별 사용 표시(강조용), [15..17] 오픈 세트 사용 표시, [18] 변형 번호(이름 뒤에 붙는 색·캐릭터 구분). (421990, 421a20)
- 작업용: `DAT_00472d60[13]` 손패 종류별 수 `C`, `DAT_00472e20[13]` 손패+오픈 세트×3 `D`, `DAT_00472d94` 오픈 세트 수. 역마다 복사본(`C`=472e60, `D`=472de0)을 새로 만들어 쓴다. (421990)

## 3. 규칙

### 3.1 배패·손패·턴
- 117장을 셔플하고 양쪽에 번갈아 11장씩 배패. 뽑으면 12장, 버리면 11장. (418bd0, 418c70, 419f30)
- 한 판은 버림 40회(양쪽 20회씩)에서 끝난다. 사람이 먼저 뽑는다. (usamain E13의 `glob140 == 40`, E11/E12가 2로 나눈 나머지로 번갈아 진행)
- 웹: 라운드 최대 20턴(한 쪽 기준), 117장, 손패 11+1. 원본: 일치. 웹은 도라 표시패를 117장 밖에 둔다고 적었으나 원본의 도라는 "종류 하나"를 가리키는 값이라 패를 따로 빼지 않는다(2.1).

### 3.2 역 필수·성립한 역의 선택
- 역 30개 중 하나 이상 성립해야 승리. 여러 개가 성립하면 점수가 가장 높은 하나만 쓰고 동점이면 번호 작은 쪽. (418e10)
- 웹: "역 필수". 원본: 일치. 성립 역 여러 개를 합산하지 않는다는 점은 RULEBOOK에 적혀 있지 않다.

### 3.3 쯔모
- 뽑은 뒤 03이 역을 찾으면 성립. 리치 여부와 무관. CPU는 항상 즉시 선언한다(usamain E15: `op_2003; jnz E26`). 사람은 버튼(17의 0xcf). (418e10, 41c800, usamain 0xdd8)
- 웹: 쯔모는 뽑은 패로 역 완성 시 선언 가능. 원본: 일치.

### 3.4 론
- 론은 상대 마지막 버림패를 자기 뽑는 칸에 넣고 03이 역을 찾을 때 성립하며, 자신이 리치 상태일 때만 가능. 사람(17 모드 0): 자신의 `glob[142]`가 0xff가 아니면(리치) 론 판정만 하고, 0xff이면(리치 아님) 펑 판정만 한다. CPU(0d): `glob[143]`이 0xff가 아니면 판정. 후리텐 검사 없음. (41c800, 41a300)
- 웹: 리치 상태에서만 론, 후리텐 없음. 원본: 일치.

### 3.5 펑
- 조건: 상대 버림이 1장 이상, 내가 리치 상태가 아님, 오픈 세트 < 3, `B[상대 마지막 버림] ≥ 2`, `2 ≤ glob[140] ≤ 0x25(37)`. (41a1b0; 사람 버튼 표시는 17에서 같은 조건에 `glob[140]` 하한 검사만 빠짐)
- 효과: 손패에서 같은 종류 2장을 빼고, 상대 버림 목록에서 마지막 1장을 빼고(리치 표시가 그 칸이면 하나 앞으로), 오픈 세트에 종류를 추가. 손패를 정렬. 손패 칸이 3칸 줄고 다음에 뽑지 않고 곧바로 버린다(usamain E30, `op_200c` 다음 `jmp E16`). 상대의 `A`가 +2. 치·깡은 없다.
- 오픈이 되면 리치 불가(3.6), 점수 75%(3.8).
- 웹: 같은 패 2장 + 상대 버림, 펑 뒤 드로우 생략. 원본: 일치하되 **원본에는 오픈 세트 3개 상한, `glob[140]` 2..37 구간 제한, 리치 중 펑 불가가 있다**(RULEBOOK 미기재).

E13은 `op_200d`(ret = 0 또는 1) 뒤 `op_2022 8`을 부르고 바로 `var31`을 검사하는데, `op_2022`는 phase 8에서 ret을 쓰더라도 0으로만 쓴다(`+0x7c`에 쓰는 곳은 0, `FUN_00421270` 인자, phase 14의 `FUN_00421540` 결과뿐). `ctx.ret`을 2로 만드는 코드가 `+0x7c` 쓰기 전수(핸들러 전체)에 없고 스크립트도 이 사이에 `st var 31`을 하지 않는다. 따라서 CPU는 상대 버림에 펑을 부르지 않는다. 사람의 펑(E41의 `op_200c`)만 있다. 웹의 CPU 펑 호출은 원본에 없는 동작이다.

## 5. CPU 버림패 선택 (418da0 → 421620)

- 리치 중이면 무조건 뽑은 패 칸. 아니면 421620:
  1. 손패 칸 i(12-3m칸, 뽑은 패 포함) 하나씩 빼본 11장으로 역 30개를 모두 판정한다.
  2. 칸 i의 `md[i]` = 부족 장수 최솟값, `sum[i]` = 30개 부족 장수의 합, `s0[i]` = 부족이 `md[i]`인 역 중 최고 점수, `s1[i]` = 부족이 `md[i]+1`인 역 중 최고 점수(기록만 하고 선택에는 쓰지 않는다).
  3. 키 `key[i] = s0[i]/100 + 1000 × (md[i] ≤ 1 ? md[i] : sum[i])`(정수 나눗셈). **키가 가장 작은 칸들**이 후보. 즉 텐파이(md=1)가 되는 버림이 우선하고, 텐파이끼리는 s0(그 칸을 버렸을 때 도달하는 최고 점수)가 낮은 쪽이, 텐파이가 아니면 모든 역의 부족 합이 작은 쪽이 이긴다.
  4. 후보 중에서 5회 셔플한 순서의 첫 칸을 고른다(동률 무작위).
- 난이도·캐릭터에 따른 차이 없음. 상대 버림, 도라, 안전도, 남은 수는 쓰지 않는다. 03이 설정하지 않은 `DAT_00472d94`(오픈 세트 수)는 직전 03 호출의 값을 재사용한다.
- 리치: 3.6. 쯔모: 항상 선언. 론: 리치 중이고 역이 있으면 항상 선언(0d에 확률 없음). 펑: 3.5 끝(경로 미해결).

### 7.2 상대 순서 (412db0) — 확정
`DAT_00473014`는 선택 때마다 스테이지 + 1이다. 선택 번호로, `rival[0..6] = {1,0,3,2,5,4,5}`(`DAT_00432a28`)이다. 상대 선택은 판마다 한 번이며 패배 후 재도전(엔트리 5로 바로 이동)은 상대를 다시 뽑지 않는다(추정).
- 플레이어가 0..5(마유 아님): 스테이지 1~4는 {0..5}에서 자기 자신·`rival[자기]`·이미 나온 캐릭터를 뺀 것 중 무작위(`rand(6)` 거절 추출, 4명이 한 번씩 나온다). 스테이지 5는 `rival[자기]`(라이벌 쌍 0↔1, 2↔3, 4↔5). 스테이지 6은 마유(6)로 고정이고 이때 마스크에 0x40을 켠다.
- 플레이어가 마유(6): 스테이지 1~5는 {0..4}에서 이미 나온 캐릭터를 뺀 것 중 무작위(`rand(6)`이 5이면 4로 바꾼다. 4가 다른 캐릭터의 두 배 확률로 먼저 나온다). 스테이지 6은 유리(5)로 고정(마스크 0x20). `rival[6] = 5`이므로 유리는 무작위 칸에는 나오지 않는다.
- 마유 "난입"의 상대 선택(412db0)에는 시간·무작위·클리어 횟수 조건이 없다. 마유가 아닌 캐릭터로 5명을 이겨 스테이지가 6이 되면 6번째 상대는 항상 마유다. 저장 데이터도 없다(저장은 `config.ini`의 BGM·SE·FAKE·EFFECT뿐). 5승 뒤 흐름은 7.6에 따로 적었다.
- 마스크 `DAT_004735c0`은 EXE 안에서 타이틀 초기화(위 표)에서만 지워진다.
