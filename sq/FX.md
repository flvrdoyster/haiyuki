# 전투 연출 (FX) — 0x11 클래스와 선언·피해 연출의 프레임 타임라인

대상: `seq/usamain.sq`(슬롯 3), `seq/usasub.sq`(슬롯 4), `seq/graph.sq`(슬롯 1), `seq/sound.sq`(슬롯 2). 프레임 번호는 연출 엔트리를 시작한 틱을 f0으로 센다. 타임라인은 `sq/tools/fxtrace.py`(스크립트 VM 시뮬레이터)가 바이트코드를 그대로 실행해 뽑은 값이다. 0x20 네이티브는 실행하지 않고, 스크립트가 읽는 값만 아는 범위에서 채웠다(아래 §3).

## 1. 엔진 모델

### 1.1 틱

- 메인 루프는 `timeGetTime()` 차이가 16ms 이상일 때마다 한 틱(`FUN_00407b50`)을 돈다. 한 틱 = 1/60초(약 16ms). 늦으면 렌더를 건너뛰고 로직 틱만 연속으로 돌아 따라잡는다. 연속 틱 한도가 `skip_limit`(`11 1e`, `DAT_00430918`)이다.
- 한 틱의 순서: 입력 갱신 → 리스트 0..N의 태스크를 순서대로 한 번씩 실행(`FUN_004010c0`) → 보이는 오브젝트를 z 오름차순으로 정렬해 변경 영역만 그림(`FUN_00407c40`, `FUN_00407ce0`, `FUN_0040f860`) → 화면 흔들림 적용 후 플립(`FUN_0040fe00`).
- 스크립트의 "프레임 경계"는 `yield`(`10 0b`), `wait N`(`10 0c`), `frame`(`11 01`), `idle`(`10 3e`), `sync 0`(`11 2e 00`), `fade_step`, `waitkey`, `waitflag/waitnflag`이다. `present`라고 부르던 `10 00`은 프레임 경계가 아니라 태스크 종료(`kill`)이다: 자기 영역을 지우도록 표시하고 오브젝트를 해제한다(`FUN_00412440` → `FUN_004011a0`).
- `wait N`은 N틱 뒤에 다음 명령으로 간다(`wait 1` = `yield`). `sync 0` + `sync 1` 한 쌍은 1틱 대기이다(`sync 1`은 렌더가 한 번 끝났을 때만 통과하는데, 로직만 도는 틱에서는 막힌다).

### 1.2 오브젝트 = 태스크

모든 태스크는 곧 스프라이트이다. 태스크 구조체(0x194바이트)의 dword 번호가 스크립트의 `var[n]`(= `setvar rN`)이다.

| var | 오프셋 | 의미 |
|---|---|---|
| 0 | +0x00 | 플래그: `0x20000000` 보임, `0x10000000` 보조 코루틴 동작, `0x40000000` 정지 |
| 5 | +0x14 | 실행 순서 키(리스트 안에서 오름차순 정렬) |
| 6 | +0x18 | 리스트 번호(`spawn`의 b6) |
| 7, 8 | +0x1c, +0x20 | x, y (16.16 고정소수, 화면 픽셀 = 값>>16) |
| 9 | +0x24 | z. 클수록 위에 그려진다. 같으면 리스트 번호·생성 순서 |
| 10 | +0x28 | 이미지 = `표면 번호 << 16 \| 프레임 번호` |
| 11 | +0x2c | 그리기 플래그. 기본값 `0x04010001` |
| 12, 13 | +0x30, +0x34 | 확대 배율 x, y (16.16). `var11 & 0x40000`일 때만 적용 |
| 25..28 | +0x64..0x70 | 충돌 사각형(`hitrect`) |
| 29 | +0x74 | `wait` 카운터 |
| 30, 31 | +0x78, +0x7c | `res`, `ret` |
| 32, 33 | +0x80, +0x84 | pc, 현재 슬롯 |
| 34, 35 | +0x88, +0x8c | `loop` 카운트, 반복 대상 |
| 45, 46 | +0xb4, +0xb8 | 보조 코루틴 pc, 보조 대기 카운터 |
| 47, 48 | +0xbc, +0xc0 | 보조 코루틴의 `loop` 카운트·대상 |
| 51 이후 | +0xcc 이후 | 스크립트가 자유롭게 쓰는 칸 (자식 포인터, 속도, 진폭 등) |

`var11` 하위 비트: `1` 색키 투명, `2` 좌우 반전, `4` 상하 반전(DirectDraw `DDBLTFX_MIRRORLEFTRIGHT`/`UPDOWN`), `0x10000` 변경 영역 단위(32×32 타일) 그리기, `0x20000` 좌표를 이미지 중심으로 해석, `0x40000` 확대. 반투명(알파)은 어디에도 없다. 투명은 8비트 팔레트의 색키 인덱스(`colorkey`)뿐이다.

태스크 사이의 값 전달은 포인터로 한다. `spawn`이 돌려주는 `res`는 자식 태스크 포인터이고, `stx [R1 + 7*4]`는 `R1`이 가리키는 태스크의 `var7`(x)에 쓴다. `bin ... mem 8`은 그 태스크의 `var8`(y)을 읽는다. 선언 연출의 부모 태스크가 자식 스프라이트 두 개의 좌표를 매 틱 직접 써 넣는 구조이다.

### 1.3 보조 코루틴 (`anim_start`, `frame`)

`anim_start E`(`11 00`)를 실행하면 그 태스크는 엔트리 E를 별도 pc로 가진 보조 코루틴을 갖는다. 매 틱 주 코드가 양보한 뒤, 보조 대기 카운터(`var46`)가 0이면 보조 코드를 한 번 실행한다. `frame w2, d4`(`11 01`)는 `var10 = d4`로 이미지를 바꾸고 `var46 = w2`로 두고 양보한다. 같은 이미지가 w2+1틱 유지된다는 뜻이다. 따라서 스프라이트 애니메이션은 `frame hold, 이미지` 명령의 나열이다.

### 1.4 리스트와 일괄 조작

`list_op mode, list`(`10 10`): 0 = 리스트의 다른 태스크를 모두 종료, 1 = 정지, 2 = 정지 해제, 3 = 숨김, 4 = 보임. 선언·나가리 연출은 리스트 1·3(판·UI)을 숨기고 리스트 2에 연출 스프라이트를 올렸다가, 끝에서 `list_op 0, 2`로 리스트 2를 비우고 `graph.sq` 엔트리 2(배경·패·키·이름 표면 다시 로드)를 호출한 뒤 리스트 1·3을 다시 보인다.

### 1.5 표면과 프레임 표

- 표면 번호 0..255. `gfx_load_*`는 `graph\<파일>.cnx`(언어판은 `graph\jp\<파일>.cnx`)를 표면에 읽는다. `b2`는 팔레트 오프셋이고 보통 21이다. `colorkey`는 같은 인덱스를 색키로 건다(`reach/pon/ron/tumo/draw/tenpai`는 23).
- 로드 4종: `gfx_load_tbl`/`gfx_load_grid`는 비디오 메모리 우선(`0x2000024`), `*_sys`는 시스템 메모리(`0x2000022`). `*_lang_*`은 경로 중간에 언어 디렉터리를 끼운 판. `*_tbl`은 프레임 표를 가리키는 엔트리 번호를, `*_grid`는 셀 크기 w×h를 받는다.
- 프레임 표(`graph.sq` 엔트리 11..20 등): 16바이트 레코드 `{x, y, w, h}`(u32 네 개)의 배열이다. 프레임 번호 k는 k번째 레코드의 원본 사각형이다. 핫스팟 필드는 없다. 그릴 때 기준점은 좌상단이고, `var11 & 0x20000`이면 이미지 중심이다. 격자형은 열 수 = 표면 너비 / 셀 너비, 프레임 k의 원본 좌표 = `((k mod 열) * 셀w, (k div 열) * 셀h)`.
- 이미지 값 `0x00220016`은 표면 0x22, 프레임 0x16이다. 표면 33(`0x21`)·34·35·36은 선언 연출의 작업 표면이다(아래 §3).

### 1.6 화면 흔들림·페이드

- 흔들림: `glob 2`가 세로 스크롤 오프셋(px), `glob 4 != 0`이면 밀려난 줄이 반대편으로 돌아오는 순환 스크롤, `glob 5`는 상태(0 없음, 1 활성, 2 마지막 틱 후 해제)이다. 틱 끝에서 `FUN_0040fe00(glob2, glob4)`가 백버퍼를 오프셋만큼 밀어 그린다.
- 페이드: 8비트 팔레트 색 10..245를 선형 보간한다. `fade_step c, n, dir`에서 c는 목표색 번호(0·1 검정, 2 흰색, 3 빨강, 4 초록, 5 노랑, 6 파랑, 7 보라), n은 총 틱 수, dir 0은 현재→목표색, 1은 목표색→원래 팔레트. 틱당 1단계이고 끝날 때까지 같은 명령에서 양보한다. `fade_end`가 저장해 둔 팔레트를 복원한다.

## 2. 사운드 호출 규약

`sound.sq`는 BGM 제어만 하는 파일이 아니다. 호출 규약(`res`에 번호를 넣고 `xcall slot2, X…`):

| 엔트리 | 동작 |
|---|---|
| X12 | 효과음: `res` 번호의 웨이브를 `haiyuki.wlk` 뱅크 0에서 생성·재생 (`flag 1` 효과음 켜짐 필요) |
| X10 | BGM 시작: `res` 번호의 곡 (`flag 0` 음악 켜짐 필요), `glob 1`에 현재 곡 번호 |
| X1 / X0 | BGM 페이드아웃(태스크 X2를 띄워 MIDI 볼륨을 틱마다 2씩 줄이고 0이면 정지) |
| X11 | BGM 즉시 정지 |

아래 표의 "SFX n"은 `res = n`으로 X12를 부른 것이고 "BGM n"은 X10이다. 번호가 어떤 소리인지는 `haiyuki.wlk`/`haiyuki.mlk`를 열어봐야 알 수 있어 이 문서에서는 다루지 않는다.

## 3. 합성 네이티브

선언·나가리 연출의 스프라이트는 비어 있는 작업 표면(33번)을 이미지로 쓴다. 표면의 내용은 매 틱 `0x20` 네이티브가 채운다.

| 호출 | 하는 일 |
|---|---|
| `20 19 00` | 백버퍼를 표면 10에 스냅샷으로 복사하고, 흰색 60%를 섞어(팔레트 최근접색 매핑, `FUN_00410840`) 표면 33→32에 둔다. 배너의 시작 위치·속도를 `var54`, `var55`에 쓴다. `flag 218`(0xda)이 꺼져 있으면 x = -512, 속도 +24px/틱, 켜져 있으면 x = 640, 속도 -24px/틱 |
| `20 19 01` | 배너 이동용: 표면 32(스냅샷)에서 `var54>>16` 위치의 폭 512×높이 176 창을 잘라 표면 33에 넣고 그 위에 글자(표면 34)를 색키로 얹는다. 화면 밖 부분은 잘라낸다 |

| `20 19 08` | `07`과 같되 조각 크기 160×176 (론·쯔모) |

## 6. 도구

`sq/tools/fxtrace.py <슬롯> <엔트리> <틱 수>`는 해당 엔트리부터 스크립트를 실행해 이벤트 로그를 출력한다. `VM(flags={…}, glob={…})`로 스크립트가 읽는 플래그·전역을 줄 수 있고(`flag 1`, `flag 3`을 켜야 효과음과 연출이 동작), `compact(vm)`이 등속 이동을 구간으로 묶는다. `0x20` 네이티브는 실행하지 않고 이벤트로만 기록한다(`20 19 00`, `20 15 02`는 스크립트가 읽는 변수를 쓰므로 그 부분만 흉내 낸다).
