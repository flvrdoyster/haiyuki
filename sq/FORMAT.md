# .sq 포맷 (환세패유기 Windows판, `haiyuki.exe`)

대상: `seq/*.sq` 7개 + `seq/jp/*.sq` 3개(총 10개). 모든 주소는 `haiyuki.exe`의 가상주소(이미지 베이스 0x400000).

## 1. 파일 구조

- 파일 머리에 u32 리틀엔디안 오프셋 표. 첫 값이 표 크기(바이트)이자 첫 엔트리 위치이므로 엔트리 수 = 첫 값 / 4.
- 엔트리 i의 영역은 `[off[i], 다음으로 큰 오프셋)`. 마지막 엔트리는 파일 끝까지. 같은 오프셋을 가리키는 엔트리가 있을 수 있다(`sound.sq` 엔트리 0과 1).
- 엔트리 주소는 로드된 파일 기준 `base + off[i]` (`FUN_00408010(슬롯, 엔트리)` = `0x408010`). 엔트리 종류는 표에 기록되어 있지 않고 참조하는 쪽이 결정한다.
  - 코드: 4바이트 단위로 정렬된 명령열. 엔트리 끝에 종결 명령이 없으면 다음 엔트리로 이어서 실행된다(`sound.sq` 엔트리 3 → 4).
  - 문자열: cp932, NUL 종결. `T` 표시 피연산자(파일 로드·그래픽 로드·오디오 로드)가 엔트리 번호로 참조한다. 파일 이름(`haiyuki.mlk`, `graph.sq`, `draw.cnx` …)과 대사가 여기에 속한다.
  - 데이터: 점프 표(u16 배열, `jtab`/`ctab`이 참조), 점프 표(u32, `xjtab`/`xctab`), 스프라이트 프레임 표(u32 배열), 역 표(`usayaku.sq`).
- 파일 끝에 4바이트 정렬용 0 패딩 1바이트가 붙는 파일이 있다(`usamain.sq`, `usasub.sq`, `Mess.sq`, `usayaku.sq`).
- 로드: `FUN_00407f60(경로, &out, 슬롯)`이 파일을 슬롯(최대 0x42 dword 간격의 슬롯 구조체 `DAT_0047d304 + 슬롯*0x108`)에 올린다. 시작: `FUN_00407940`(0x407940)이 `<seq 디렉터리>startup.sq`를 `FUN_00408040(경로, 슬롯 0, 엔트리 0)`으로 시작한다.

슬롯 배정(`startup.sq`의 `load_sq`/`load_sq_lang`):

| 슬롯 | 파일 |
|---|---|
| 0 | startup.sq |
| 1 | graph.sq |
| 2 | sound.sq |
| 3 | usamain.sq |
| 4 | usasub.sq |
| 5 | jp/usayaku.sq (`load_sq_lang`) |
| 6 | jp/serifu1.sq (`load_sq_lang`) |
| 21 | tlogo.sq |
| 22 | tchrsel.sq |
| 23 | jp/Mess.sq (`load_sq_lang`) |

`load_sq_lang`(`10 31`)은 스크립트 디렉터리와 파일 이름 사이에 언어 디렉터리 `DAT_00476f20`(`jp` 등)을 끼운다.

## 2. 실행 모델

- 인터프리터 `FUN_004080c0`(0x4080c0). 태스크(ctx)마다 `ctx+0x80`이 pc. 명령 첫 바이트 `c`로 분기한다.
  - `c < 0x10`: 기본 명령. 표 `0x42e038`(16칸, 13개 정의).
  - `0x10`: 표 `0x430790`(범위 검사 `byte1 <= 0x51`).
  - `0x11`: 표 `0x42ff70`(`byte1 <= 0x41`).
  - `0x12`: 표 `0x430490`(`byte1 <= 0x50`).
  - `0x20`: 표 `0x4443c8`(검사 없음, 정의된 것은 0x00~0x2b).
  - `0xa0`: 표 `0x42f048`(검사 없음, 정의된 것은 0x00~0x0b 중 일부).
  - 그 밖의 첫 바이트는 아무것도 하지 않고 같은 pc에서 반복한다. 표의 미정의 칸(`0x410bc0`)도 pc를 진행시키지 않는다.
- 핸들러가 `DAT_0047d1f8 = 1`로 두면 현재 프레임의 이 태스크 실행이 끝난다(양보). 태스크 생성은 `FUN_00401070(FUN_004080c0, 우선순위)`, 첫 실행은 즉시 한 번.
- 모든 명령은 4바이트 배수 길이(4, 8, 12). 첫 바이트가 클래스, 둘째 바이트가 클래스 안의 번호(기본 명령에서는 서브옵).
- 태스크 컨텍스트 주요 필드:

| 오프셋 | 의미 |
|---|---|
| +0x00 … +0x7c | 지역 변수 `var[0..0x1f]` (dword). `var[0x1e]` = `+0x78` = 조건/결과 레지스터(`res`), `var[0x1f]` = `+0x7c` = 반환값 레지스터(`ret`) |
| +0x74 | 대기 카운터 |
| +0x80 | pc |
| +0x84 | 현재 슬롯 번호 |
| +0x88, +0x8c | `loop` 반복 횟수, 반복 대상 주소 |
| +0x90 | 콜 스택 깊이(최대 4) |
| +0x94 .. | 호출 시 저장한 슬롯 스택 |
| +0xa4 .. | 호출 시 저장한 반환 pc 스택 |
| +0x138 | 오디오 핸들 |
| +0x13c | 오브젝트 배열 포인터(`obj[n]`) |

- 전역 레지스터 `R[0..200]`(`DAT_00475cc0`, 범위 검사 `> 200`은 `DebugBreak`), 전역 배열 `glob[]`(`DAT_00476100`), 플래그 배열(`FUN_00412030`/`FUN_00412060`로 읽고 쓰는 비트 플래그)이 있다.

## 3. 기본 명령 (0x00 ~ 0x0c)

레지스터 기반 계산 명령. 바이트 1 = 서브옵 `s`, u16@2 = 대상 레지스터 `d`. 길이는 표의 값.

| 바이트 | 니모닉 | 길이 | 형태 | 핸들러 |
|---|---|---|---|---|
| 00 | ldsys | 4 | `R[d] = sys(s)`; s=0x1a 스틱(`DAT_00476d7c<<16 + DAT_00476d78`), 0x1b 눌린 순간 비트, 0x1c 눌려 있음 비트 | 0x4014c0 |
| 01 | ld | 8 | `R[d] = load(s, d32@4)` | 0x401570 |
| 02 | ld | 8 | `R[d] = load(s, R[w@4])` | 0x4016c0 |
| 03 | bin | 12 | `R[d] = bin(s, R[w@4], d32@8)` | 0x401720 |
| 04 | bin | 12 | `R[d] = bin(s, d32@4, d32@8)` | 0x401970 |
| 05 | bin | 12 | `R[d] = bin(s, d32@4, R[w@8])` | 0x4019d0 |
| 06 | bin | 8 | `R[d] = bin(s, R[w@4], R[w@6])` | 0x401a40 |
| 07 | st | 8 | `store(s, d32@4, R[d])` | 0x401ab0 |
| 08 | st | 8 | `store(s, R[w@4], R[d])` | 0x401bb0 |
| 09 | stx | 12 | `mem[R[w@4] + d32@8*4] = R[d]` (s=0x1e) | 0x401c10 |
| 0a | stx | 12 | `mem[d32@4 + d32@8*4] = R[d]` | 0x401cb0 |
| 0b | stx | 12 | `mem[d32@4 + R[w@8]*4] = R[d]` | 0x401d10 |
| 0c | stx | 8 | `mem[R[w@4] + R[w@6]*4] = R[d]` | 0x401d70 |

범위를 벗어난 서브옵은 `MessageBox("Calculation error N")` 후 종료(N = 1~5가 각각 `0x401520`, `0x4015d0`, `0x401b10`, `0x401790`, `0x401c70`).

`load` 서브옵(`FUN_004015d0`): 0x11 `x == 0`, 0x12 `var[x]`, 0x16 `obj[x]`, 0x17 현재 슬롯의 엔트리 x 주소, 0x18 `glob[x]`, 0x19 플래그 x, 0x1d `FUN_00401490(x)`(시스템 값), 0x20 즉시값 x.

`bin` 서브옵(`FUN_00401790`, a=첫 피연산자, b=둘째): 2 `a*b`, 3 `a/b`(0 나눗셈이면 "Division by 0" 후 종료), 4 `a+b`, 5 `a-b`, 6 `a<<b`, 7 `a>>b`(산술), 8 `a<b`, 9 `a<=b`, 10 `a>b`, 0x0b `a>=b`, 0x0c `a==b`, 0x0d `a!=b`, 0x0e `a&b`, 0x0f `a^b`, 0x10 `a|b`, 0x1e `mem[a+b*4]`, 0x1f 슬롯 a의 엔트리 b 주소.

`store` 서브옵(`FUN_00401b10`): 0x12 `var[x] = v`, 0x16 `obj[x] = v`, 0x18 `glob[x] = v`, 0x19 플래그 x = v.

조건 분기는 별도 명령이 없고 `bin`/`ld`로 구한 값을 `st var 30, R`(= `ctx.res`)에 넣은 뒤 `jnz`·`cnz`·`xjnz`·`jidx` 등을 쓴다. 호출 결과는 `ld R, var 31`(= `ctx.ret`).

## 4. 확장 명령

표의 "길이"는 핸들러가 pc에 더하는 값(또는 점프 명령은 이동 후 위치가 무관해 호출 규약으로 정한 값). 피연산자 열의 `b/w/d` 뒤 숫자는 명령 안의 바이트 오프셋, `E`는 같은 슬롯의 엔트리 번호, `T`는 문자열 엔트리 번호, `S`는 슬롯, `X`는 다른 슬롯 안의 엔트리 번호, `g`는 `glob` 번호이다. 의미 칸이 "미상"인 항목은 길이·피연산자 위치만 핸들러에서 읽어 확정했고 용도는 모른다. 피연산자 열은 핸들러가 읽는 필드의 자동 추출 결과이며, 같은 오프셋을 여러 폭으로 읽는 명령은 가장 넓은 것만 표시한다.

- 엔트리 2: u32 역 수(30), 이어서 역이 연속한다.
- 역 하나(로더가 읽는 순서):
  1. 이름: cp932, NUL 종결, 다음 4바이트 경계까지 NUL 패딩.
  2. 설명 줄들: 각각 cp932, NUL 종결(패딩 없음). 빈 문자열(NUL 하나)이 나오면 줄 목록이 끝난다.
  3. 4바이트 경계까지 패딩.
  4. u32 점수(예 2400, 8000, 12800).
  5. u32 12개: 패 번호. `255`는 아무 패.
- `yaku.tsv`의 마지막 열은 설명 줄 목록 끝(빈 문자열)과 정렬 패딩 뒤부터 12개 패 번호 끝까지의 u32를 원문 그대로 적은 것이므로, 줄 목록 종결 NUL이 4바이트 경계에서 u32 0으로 보이는 역에서는 점수 앞에 0이 하나 더 붙는다. 이 0은 패딩이다.
- 파일은 0xf70에서 끝나고 0xf71에 패딩 1바이트가 있다.

## 7. 규칙·AI가 어디 있는가

- 마작 규칙(패산 `DAT_004756e0`(0x75칸 순환), 뽑기 위치 `DAT_004760f8`, 플레이어별 패/버림 영역, 역 판정, 점수)은 EXE의 `0x20` 클래스 내장 루틴(44개, 디컴파일 텍스트 합계 약 140KB)에 있다. 예: `0x20 0a`(0x419f30)는 패 뽑기·패산 포인터 이동·패 영역 갱신, `0x20 0e`(0x41a3f0)는 역 표 적재.
- `usamain.sq`는 이 루틴들을 `op_20xx`로 호출하며 사이사이에 연출을 넣는 진행 스크립트이고 `usasub.sq`는 `0x20` 호출이 거의 없는 연출 스크립트다. 따라서 규칙과 AI 판단은 EXE 쪽에 있고, 스크립트에는 호출 순서와 분기만 있다.
- AI 판단 루틴이 `0x20` 클래스 중 어느 것인지는 아직 특정하지 않았다(큰 후보: `0x20 07` 0x4190e0, `0x20 08` 0x419820, `0x20 15` 0x41b910, `0x20 19` 0x41cd40, `0x20 22` 0x41ef60).

## 8. 아직 모르는 것

- `0x20` 클래스 44개의 개별 의미(합성 네이티브 `20 19`, `20 15`, `20 27`은 `FX.md` §3에 개요), `0x11` 클래스의 `11 0e`, `11 2a`..`11 2d`(`11 2b`는 FUN_004051c0 호출, `11 2c`/`11 2d`는 그래픽 디렉터리 파일 로드), `0x10` 클래스의 `FUN_00405xxx` 호출(0x22~0x29)의 용도, `0x12` 클래스의 `0x40`~`0x4d`(0x40e3c0 이후 루틴).
- 기본 명령 `load` 서브옵 0x1d가 읽는 시스템 값(`FUN_00401490`)의 목록.
- `0x10 05`의 b6(우선순위로 보이나 의미 미확인), `ctx.res`를 쓰는 명령과 읽는 명령의 전체 대응.
- 엔트리가 코드인지 데이터인지는 참조하는 명령을 보고 정해지므로 디스어셈블러는 "끝까지 명령으로 읽히고 길이가 엔트리 끝과 맞으면 코드, 아니면 문자열·데이터"라는 규칙을 쓴다. 우연히 명령처럼 읽히는 데이터 엔트리는 코드로 오인될 수 있다.
- `Ghidra`가 디컴파일한 `0x401bb0`, `0x410bc0` 등 일부 핸들러는 함수로 인식되지 않아 별도로 함수를 생성해 내보냈다(`extracted/sq/ghidra/decomp/handlers.c`).

## 9. 산출물

- `sqdis.py <파일.sq>`: 디스어셈블러(표준 라이브러리만). 요약 통계는 stderr.
- `extracted/sq/dump/*.txt`: 10개 파일 전체 덤프(ignore 폴더, `sqdis.py`로 다시 만든다).
- `yaku.tsv`, `yakutsv.py`: 역 표 추출.
- `ghidra/`: 내보내기 스크립트. Ghidra 프로젝트(`hy.gpr`)와 `decomp/all.c`(전 함수)·`decomp/handlers.c`(명령 핸들러)는 `extracted/sq/ghidra/`(ignore 폴더).
- `tools/`: 핸들러 표 추출에 쓴 보조 스크립트와 스크립트 VM 시뮬레이터 `fxtrace.py`.
- `FX.md`: 0x11 클래스 의미, 객체 모델, 선언·피해 연출 타임라인, 웹과의 차이.
