# 목표와 방향(고정)

1. **캐릭터 시트는 고정이다.** 비기의 비용·효과·제한, `luck`, 역·점수 규칙은 캐릭터의 개성이며 이번 작업에서 바꾸지 않는다. 시트 체급은 대칭 모드(실력 1.0 양쪽, `skillOffset` 0, luck 캐릭터별)로 잰 `de0ac36` 결과를 참고치로 둔다(눈썹개 60.8 … 페톰 35.8).
2. **잡는 것은 CPU 밸런스 하나다.** 같은 난이도에서 어느 상대를 골라도 사람이 매치(KO)를 이길 확률이 비슷하게(평탄화). 스토리 순서에 따른 난이도 곡선은 만들지 않는다. 난이도의 축은 난이도 선택 하나뿐이다.
3. **CPU 레버는 두 개뿐이다.** 캐릭터별 `skillOffset`(실력 보정)과 쉬움 모드 드로우 어시스트. CPU가 펑·비기·리치를 "덜 하게" 만드는 CPU 전용 규칙은 추가하지 않는다(실력 보정이 확률을 낮추는 것은 기존 난이도 메커니즘이므로 허용).
4. **측정의 단위는 매치(KO) 승률이다.** 라운드 승률은 보조 지표로만 적는다.
5. **측정 구도는 "고정 기준 P1 vs 보정 적용 CPU 캐릭터"다**(`_ai_fingerprint` 구도). 대칭 모드는 시트 체급을 재는 도구이고 CPU 밸런스 판정에는 쓰지 않는다.
6. **기준 조건은 난이도 보통**(`cpuSkill` 밴드 0.75→0.95 + 캐릭터 `skillOffset`), 기준 P1은 `AutoPlay`의 중립 플레이(`decideDiscard(hand, 0.7, …)`, 비기는 P1 캐릭터 것을 그대로 사용, luck 캐릭터별 적용). P1 캐릭터는 7명을 고르게 돌린다(상대와 다른 캐릭터).
7. **합격 기준**: 난이도 보통에서 각 CPU 캐릭터의 매치 승률이 전 캐릭터 평균 ±5%p 안. 절대값이 아니라 평탄함을 본다. 어려움은 평탄화하지 않는다. 실력 1.0은 그 위가 없어 보정으로는 깎는 것만 가능하고, 그러면 어려움이 약한 캐릭터의 천장에 맞춰 내려온다. 어려움에서는 `skillOffset`을 0으로 끄고(`difficulty === 'hard'`면 `cpu.skillOffset = 0`) 모든 CPU가 최선을 다하는 상태에서 캐릭터 간 체급 차이가 그대로 드러나게 둔다. 어려움 밴드 재설계는 하지 않는다.
8. **표본·보고 형식 고정**: 캐릭터당 100경기 이상, 95% 구간 병기, 표 열은 [캐릭터 | 매치 승률 % ± | 라운드 승률 % | 경기당 라운드 | 평균 득점 | 방총률 % | 비기/경기 | 끝 MP R1/R2/R3+]. 보고 첫 줄은 "±5%p 밖 캐릭터" 목록. 비교는 항상 직전 시행의 같은 표와 나란히.

측정 절마다 첫 줄에 "이 틀의 어느 항목을 재는지"를 적는다. 아래 "대칭 밸런스 기준선" 이하 절은 항목 1(시트 체급)을 재는 대칭 모드 측정이다.
